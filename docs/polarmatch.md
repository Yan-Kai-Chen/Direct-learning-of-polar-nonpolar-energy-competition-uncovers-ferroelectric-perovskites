# PolarMatch: Establishing Phase Correspondence

This module trains a two-tower graph encoder to retrieve nonpolar candidates for
polar query structures.

## Evaluation protocol

The tracked split is a polar-identity holdout. Polar structures cannot appear
in both train and test. Nonpolar candidates may be reused across the two sets;
the audit reports that overlap explicitly.

Run the split audit from the repository root:

```bash
polarmatch-check-split \
  --train-pairs data/polarmatch/splits/train_pairs_pos.csv \
  --test-pairs data/polarmatch/splits/test_pairs_pos.csv
```

The split is not regenerated by the training script.

## Training

Supply a local CIF directory, update `paths.struct_dir` in
`configs/polarmatch/train_pair_retriever.yaml`, then run from the repository root:

```bash
polarmatch-train --config configs/polarmatch/train_pair_retriever.yaml
```

The default model uses a GINE encoder with radial edge embeddings and an
InfoNCE retrieval objective. An optional symmetry term and score adjustment are
declared in the YAML configuration.

The score adjustment is:

```text
adjusted_score =
    base_score
    + 0.15 * clip((operations_nonpolar - operations_polar) / 192, -1, 1)
```

Its implementation is also exposed in `polarmatch.protocol` for independent
testing.

Full training is not run by repository tests. Outputs, graph caches, and
weights are local artifacts and are ignored by Git.

Retrieval scores propose correspondences; they do not prove a group-subgroup
embedding. PolarEvolve exposes separate crystallographic relation compilers.
